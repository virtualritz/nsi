# Plan: ɴsɪ Parsing

## Status

Implemented, apart from throughput. The reader, the Lua interpreter and
compressed input are all gated; what remains is measuring the allocation
behaviour the design was built for, and the statements neither gate
drives.

## Approach

Three layers, each testable without a renderer:

1. **Lex** -- `&[u8]` to tokens. Borrowing, no allocation.
2. **Parse** -- tokens to statements, applied to the sink as each one
   completes. This is where the keyword-terminated rule lives.
3. **Apply** -- build `nsi_ffi_wrap::Arg` in reused scratch and call the
   sink.

Lua sits beside all three: it is an interpreter, not a parser, and
shares only the sink.

## Gates

| Gate | Command | Met |
| --- | --- | --- |
| Round-trip through the writer | `cargo test -p nsi-parse --test roundtrip` | yes |
| **Against 3Delight's own output** | `cargo test -p nsi-parse --test renderdl` | yes |
| Lua round-trip | `cargo test -p nsi-parse --features lua` | yes |
| Compressed input | `cargo test -p nsi-parse --features gzip,zstd` | yes |
| No steady-state allocation | `cargo test -p nsi-parse --test allocation` | no |
| No warnings | `cargo clippy -p nsi-parse --all-targets -- -W warnings` | yes |

The second is the meaningful one, for the same reason it is in `003`:
it holds the crate against a production renderer rather than against
itself. Its input is generated by `renderdl -cat`, so the corpus is
whatever 3Delight actually writes.

## Order

Correctness first, then speed. `research.md` D4.

1. Lexer and the keyword-terminated grammar, with the one-line-scene

2. The nine statements, then the argument types.
3. The two round-trip gates.
4. Errors with offsets.
5. Compressed input.
6. Lua.
7. Scratch reuse, borrowing, and the throughput number.
